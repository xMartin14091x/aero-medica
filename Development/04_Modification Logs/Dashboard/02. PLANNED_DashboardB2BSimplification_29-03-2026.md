## Problem Statement

**KP:** The current Dashboard was built with an "Instructor Dashboard" framing — 3 tabs including a "Class Overview" tab with mock student data (5 fake students, RNG seed 42). This doesn't align with the B2B business model where AeroMedica is sold to institutions, not used as a classroom management tool. The player needs to see only their own performance data, updated immediately after completing a scenario. The instructor/class management layer is out of scope for the prototype.

## Proposed Solution

**MT:** Strip the Dashboard down to 2 tabs focused entirely on the player's own data from HistoryManager. Remove all mock student generation, peer comparison, and class statistics. Ensure data refreshes from disk every time the Dashboard is opened (not cached from startup).

## Architecture Decisions

**MT:** No new architecture required. This is a simplification — removing layers, not adding them. HistoryManager's existing API (`get_all_history`, `get_history`, `get_improvement`) already supports everything needed. The scoring engine and radar chart components are untouched.

One note: the existing `_inject_real_session_data()` flow that reads from ScenarioManager.get_last_results() is being removed. Instead, the standard flow is: scenario ends -> ScoringEngine computes -> HistoryManager.save_session_scores() -> player navigates to Dashboard -> Dashboard reads HistoryManager. This is cleaner and already works.
