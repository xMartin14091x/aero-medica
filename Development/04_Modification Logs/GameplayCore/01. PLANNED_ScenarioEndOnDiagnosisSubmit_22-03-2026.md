# MOD-GC-01 — Scenario Ends When Diagnosis is Submitted

**Date:** 22-03-2026
**Requested by:** Chief Manager Martin
**Status:** `[x] Complete`
**Priority:** High (competition week)

## Summary

Currently, when a patient's diagnosis is submitted, the scenario only ends for that patient's interaction (3s delay then closes UI and calls `end_scenario`). For multi-patient scenarios, the player should be able to submit diagnoses for each patient, and the scenario ends when ANY diagnosis is submitted (not requiring all patients to be diagnosed).

Chief Manager Martin's direction: When a diagnosis is submitted for a patient, the scenario stage ends — triggers debrief/scoring screen immediately after the 3-second feedback delay.

## Current Behavior

`patient_interaction_ui.gd:2338-2343` — `_on_diagnosis_timeout()` already calls `scenario_mgr.end_scenario()` after a 3s delay. This already works for single-patient scenarios (tutorial). For multi-patient scenarios, this should also work since it calls `end_scenario()` on first submission.

## Verification Needed

Confirm that in multi-patient scenarios:
1. Submitting diagnosis for ANY patient triggers `end_scenario()`
2. The debrief screen shows summaries for ALL patients (assessed or not)
3. Patients without diagnosis submission show "none submitted" in the review

If this already works (which the code suggests), mark as VERIFIED. If not, modify `_on_diagnosis_timeout()` to always call `end_scenario()` regardless of patient count.

## Files

- `scripts/ui/patient_interaction_ui.gd` — `_on_diagnosis_timeout()`
- `scripts/core/scenario_manager.gd` — `end_scenario()`, `_build_patient_summaries()`

## Acceptance Criteria

- [ ] Submitting diagnosis for one patient ends the scenario
- [ ] Debrief screen shows all patients (assessed and unassessed)
- [ ] AI reviewer receives data for all patients
