# BUG-GC-02 — ActionMenu Artifact Popup & Player Movement Lock During Chat UI

**Date:** 21-03-2026
**Reported by:** Chief Manager Martin (live testing)
**Severity:** Medium
**Status:** `[x] Complete`

---

## Bug A — ActionMenu Artifact Popup on Patient Interaction

**Symptom:** When pressing E to open the PatientInteractionUI (Chat UI), a small popup appears behind/alongside it — the old ActionMenu (ABCDE assessment menu). This is a visual artifact that should not appear.

**Root Cause:** In `patient_interaction_ui.gd:open_ui()`, `_assessment_manager.begin_assessment(patient)` is called on line 237, which emits `assessment_started`. HUDController catches this signal and checks if PatientInteractionUI is visible (line 84) — but `visible = true` doesn't happen until line 257. The visibility check fails, so ActionMenu opens erroneously.

**Fix:** Move `visible = true` before the `begin_assessment()` call so that HUDController's guard clause correctly detects the PatientInteractionUI is active.

**Files:**
- `scripts/ui/patient_interaction_ui.gd` — reorder visibility before begin_assessment

---

## Bug B — Player Movement Not Locked During Chat UI

**Symptom:** When the PatientInteractionUI is open and the player types W, A, S, or D in the chat input field (LineEdit), the character moves. Movement should be locked while the UI is open.

**Root Cause:** `player_controller.gd:_physics_process()` uses `Input.get_axis()` which reads raw input state regardless of UI focus. No guard check exists for UI-active state.

**Fix:** Add a guard at the top of `_physics_process()` that checks `Input.mouse_mode == Input.MOUSE_MODE_VISIBLE` (set by PatientInteractionUI on open). When the cursor is visible (any modal UI active), skip all movement input and zero velocity.

**Files:**
- `scripts/gameplay/player_controller.gd` — add UI-active guard in _physics_process
