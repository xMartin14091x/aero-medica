# BUG-GC-03 — Camera Zoom Passthrough During UI Scroll

**Date:** 22-03-2026
**Reported by:** Chief Manager Martin (live testing)
**Severity:** Medium
**Status:** `[x] Complete`

---

## Symptom

When the PatientInteractionUI is open and the player scrolls within the UI (e.g., scrolling through exam results, chat history, or equipment list), the isometric camera zoom also changes. The mouse wheel event passes through the UI to the camera.

## Root Cause

`isometric_camera.gd:39-46` uses `_unhandled_input()` to catch mouse wheel events for zoom. However, when PatientInteractionUI is open, scroll events inside a `ScrollContainer` are consumed by the UI for scrolling content — BUT if the mouse is outside the ScrollContainer area or the scroll event propagates, it also reaches `_unhandled_input` and changes camera zoom.

The PatientInteractionUI sets `mouse_filter = MOUSE_FILTER_STOP` (line 151) which blocks mouse click/move events, but `_unhandled_input` receives events AFTER the GUI system — if the GUI doesn't fully consume the scroll event, it leaks through.

## Fix

Add a guard in `isometric_camera.gd:_unhandled_input()` to skip zoom when `Input.mouse_mode == Input.MOUSE_MODE_VISIBLE` (same pattern as the movement lock fix in BUG-GC-02).

## Files

- `scripts/core/isometric_camera.gd` — add UI-active guard for scroll zoom

## Acceptance Criteria

- [ ] Scrolling within PatientInteractionUI does not change camera zoom
- [ ] Camera zoom works normally when no UI is open
- [ ] Camera zoom works normally in pause menu (paused state)

## Resolution
**Fixed in:** Phase 7-8 (UI Refactor)
**Fix:** `patient_interaction_ui.gd` sets `mouse_filter = Control.MOUSE_FILTER_STOP` on the main UI panel and background, preventing scroll events from passing through to the isometric camera. The background ColorRect also uses `MOUSE_FILTER_STOP`.
