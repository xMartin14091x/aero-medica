# BUG-GC-05 — Vital Signs Showing Generic "Assessed" Instead of Values

**Date:** 22-03-2026
**Reported by:** Chief Manager Martin (live testing)
**Severity:** Low-Medium
**Status:** `[ ] PENDING`

---

## Symptom

In the Exam tab of PatientInteractionUI, some vital sign assessments display generic "Assessed" text instead of actual values (e.g., temperature should show "Temp: 36.8°C" but may show "Assessed"). Skin assessment correctly shows "NORMAL/WARM/MOIST".

## Root Cause (Suspected)

In `patient_interaction_ui.gd:_display_vital_result()`, if `display_text` remains empty after the match block, the fallback at line 1644-1645 returns: `result.get("description", result.get("text", "Assessed"))`.

This can happen if:
1. The `perform_assessment()` result dict has different keys than expected by `_display_vital_result`
2. The `_read_vital_from_patient()` fallback returns a dict with keys that don't match the display function's expectations
3. The `perform_assessment()` returns empty dict (`{}`) due to assessment state mismatch, triggering fallback which then also fails

Skin works because its match clause checks `result.has("color")` which matches both `perform_assessment` and `_read_vital_from_patient` outputs.

## Fix

1. Audit key consistency between `assessment_manager.gd:_read_assessment()`, `patient_interaction_ui.gd:_read_vital_from_patient()`, and `_display_vital_result()`
2. Add defensive fallback: if display_text is still empty after match, attempt to format any numeric value found in the result dict
3. Log when fallback "Assessed" text is used (debug probe for INDEV)

## Files

- `scripts/ui/patient_interaction_ui.gd` — `_display_vital_result()`, `_read_vital_from_patient()`
- `scripts/gameplay/assessment_manager.gd` — `_read_assessment()` return key consistency
