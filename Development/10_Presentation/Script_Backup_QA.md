## Q1: "ข้อมูลทางการแพทย์ถูกต้องแค่ไหน? ใครเป็นคนตรวจสอบ?"

ข้อมูลทางการแพทย์ทุกชิ้นในเกมผ่านกระบวนการตรวจสอบความถูกต้องทางคลินิกครับ

สัญญาณชีพ อาการ และคำวินิจฉัยของผู้ป่วยทุกคนถูก Cross-check กับ Triage category ที่ควรได้ ตัวอย่างเช่น ผู้ป่วยที่ HR 135, BP 75/45, SpO2 91% ต้องเป็น RED — Immediate ไม่ใช่ YELLOW

สำหรับ Protocol เฉพาะทาง เราตรวจสอบ 3 จุดสำคัญตาม ACLS 2020: หนึ่ง — Amiodarone ไม่ Convert VFib ได้เอง ต้องใช้ AED Shock เท่านั้น สอง — Atropine ถูกถอดออกจาก Cardiac Arrest Algorithm ตั้งแต่ AHA 2010 ในเกมให้ Atropine กับผู้ป่วย Arrest ระบบจะแจ้งว่าไม่เหมาะสม สาม — หลัง ROSC ใช้ Infusion ไม่ใช่ Bolus

นอกจากนี้ผู้ป่วยทุกคนมี Severity Markers ใน Head-to-Toe: สีแดงคือวิกฤต สีเหลืองคือสำคัญ สีเขียวคือปกติ รวม 216 รายการที่ถูกจัดระดับทั้งหมดครับ

## Q2: "ใช้เทคโนโลยีอะไร? ทำไมถึงเลือก?"

เราใช้ Godot 4.6 เป็น Game Engine ครับ เลือกเพราะเป็น Open Source, รองรับ Cross-platform, และมีขนาดเล็ก ติดตั้งง่าย

AI ใช้ Ollama กับ llama3.1:8b เลือกเพราะทำงานออฟไลน์ได้ 100% ไม่ต้องพึ่งพา Cloud API ข้อมูลไม่ออกนอกเครื่อง

สถาปัตยกรรมเป็น 6 ชั้น: Scene Layer สำหรับแต่ละสถานการณ์, UI Layer สำหรับหน้าจอทั้งหมด, Manager Layer สำหรับจัดการ State, Medical Layer สำหรับระบบทางการแพทย์, AI Layer สำหรับ Ollama และ Fallback, และ Data Layer ที่ทุกอย่างขับเคลื่อนด้วย JSON

ระบบมี Autoload Singleton 13 ตัวที่ทำงานอัตโนมัติตลอดเกม เช่น GameManager, ScenarioManager, TelemetryCollector, ThemeMedical ครับ

## Q3: "มีกี่สถานการณ์? แต่ละอันต่างกันอย่างไร?"

มี 5 สถานการณ์ที่เล่นได้ครับ ไล่ระดับจากง่ายไปยาก

Tutorial — 1 ผู้ป่วย ไม่จำกัดเวลา ใช้กระเป๋า BLS เหมาะสำหรับเรียนรู้

Road Traffic Accident — 3 ผู้ป่วย จำกัด 10 นาที ต้องจัดลำดับความสำคัญ

Cardiac Arrest — 1 ผู้ป่วย จำกัด 5 นาที เน้น CPR + AED ถ้า Shock สำเร็จมีโอกาส ROSC 70%

Building Fire — 3 ผู้ป่วย จำกัด 8 นาที มี Hazard Zone ไฟทำอันตรายผู้เล่น ยืนนาน 15 วินาที EMT หมดสภาพ

Mass Casualty — 6 ผู้ป่วย บวกอีก 1 คนที่เข้ามาระหว่างเล่น จำกัด 15 นาที อุปกรณ์ถูกเพิ่มเป็น 2.5 เท่า แต่ก็ยังไม่พอสำหรับทุกคน ต้องตัดสินใจว่าจะจัดสรรให้ใคร

ผู้ป่วยทุกคน Deteriorate ตามเวลาจริง ถ้าไม่รักษาจะเปลี่ยนจาก Conscious เป็น Unconscious เป็น Cardiac Arrest จนเสียชีวิตได้ครับ

## Q4: "ถ้าเครื่องรัน AI ไม่ได้จะเป็นอย่างไร?"

เกมทำงานได้เหมือนกันทุกประการครับ สิ่งที่เปลี่ยนมีแค่ 2 อย่าง

บทสนทนาผู้ป่วย — แทนที่ AI จะสร้างคำตอบแบบ dynamic ระบบจะใช้คำตอบที่เตรียมไว้ล่วงหน้าจากข้อมูลใน Scenario JSON

AI Review — แทนที่จะวิเคราะห์ Telemetry เฉพาะเซสชัน ระบบจะใช้ Cached Review ที่เตรียมไว้ 70 รายการ ครอบคลุม 7 สถานการณ์ คูณ 5 ระดับผลงาน คูณ 2 ภาษา เลือกอัตโนมัติตามคะแนนรวมของผู้เล่น

ระบบ Scoring, Triage, Deterioration, อุปกรณ์ การให้ยา ทุกอย่างทำงานเหมือนกันหมด

เมื่อเปิดเกม ระบบจะ Probe หา Ollama อัตโนมัติบน localhost และ IP ทุกตัวในเครือข่าย ใช้เวลา 4 วินาที ถ้าไม่พบจะแจ้งผู้เล่นด้วย Popup แล้วเข้าสู่โหมด Fallback โดยอัตโนมัติ ผู้เล่นกด Reconnect ได้ทุกเมื่อใน Settings ครับ

## Q5: "พัฒนาภายใน 25 วันได้อย่างไร?"

เราใช้กระบวนการ Agile Iterative แบบ Phase-based 9 เฟสครับ แต่ละ Phase ส่งมอบส่วนที่ใช้งานได้

Phase 0-1 สร้างโครงสร้างพื้นฐานและ Core Gameplay ภายใน 4 วัน Phase 2-3 เพิ่มระบบทางการแพทย์และ AI Pipeline อีก 4 วัน Phase 4-6 เพิ่มสภาพแวดล้อม UI ขั้นสูง และ Scoring อีก 6 วัน Phase 7 แก้ Bug 22 ตัว ทดสอบ E2E ทุกสถานการณ์ Phase 8 Polish สุดท้าย รวม UI Revamp v2.0 ระบบสองภาษา Cached Review และ 3D Assets

ทุกการเปลี่ยนแปลงต้องมี Ticket ก่อนเขียนโค้ด ทุกเซสชันถูกบันทึกใน Development Log ทำให้ติดตามได้ว่าทำอะไรไปเมื่อไหร่ ตัดสินใจอะไรเพราะอะไร

เราเปิดเผยเครื่องมือ AI ที่ใช้ทั้งหมดใน CONTRIBUTION.md — Ollama สำหรับ AI ในเกม, Claude สำหรับช่วยเขียนโค้ด, Gemini สำหรับ Brainstorming และภาพ ทีมเป็นผู้ตัดสินใจและควบคุมทุกจุดครับ

## Q6: "มีแผนพัฒนาต่ออย่างไร?"

มี 2 ส่วนหลักครับ

ส่วนแรก — Instructor Web Dashboard ระบบเว็บให้ผู้สอนเปิด browser ดูข้อมูลนักเรียนแบบ real-time ผ่าน LAN เห็นว่าใครกำลังเล่นฉากอะไร คะแนนเท่าไหร่ ติดขัดตรงไหน ใช้ FastAPI กับ SQLite ถ้า server ปิดอยู่ข้อมูลจะ queue ไว้แล้วส่งเมื่อเปิด แผนนี้เขียน Ticket ครบ 8 ใบ ได้รับการอนุมัติแล้วรอดำเนินการ

ส่วนที่สอง — v2.0 Features ตามคำแนะนำจากอาจารย์ที่ปรึกษา ได้แก่ Step-Up Timer ผู้ป่วยที่ไม่ถูกประเมินเสื่อมถอยเร็วขึ้น บังคับให้ Triage จริง, Adverse Drug Effects ให้ยาผิดเห็นผลเสียบนจอ, และ Simplified Mode สำหรับคนทั่วไปที่ไม่ใช่บุคลากรทางการแพทย์

สถานการณ์ใหม่เพิ่มได้ง่ายเพราะขับเคลื่อนด้วย JSON ไม่ต้องแก้โค้ดครับ

## Q7: "ต่างจากเครื่องมือฝึกอบรมอื่นอย่างไร?"

จุดต่างหลัก 3 ข้อครับ

หนึ่ง — Offline-first พร้อม AI ไม่มีเครื่องมืออื่นที่รวม Local AI กับ Zero Cloud Dependency ในตัวเดียว เครื่องมือส่วนใหญ่ต้องต่ออินเทอร์เน็ตหรือพึ่ง Cloud

สอง — Full Protocol Coverage ครอบคลุมตั้งแต่ DRSABCDE จนถึงการวินิจฉัยแยกโรค 47 อาการในระบบเดียว ไม่ใช่แค่ Quiz หรือ Multiple Choice แต่ต้องลงมือทำจริง

สาม — Zero Infrastructure Cost สถาบันไม่ต้องจ่ายค่า server ค่า subscription ค่าอุปกรณ์เพิ่ม แค่มีคอมพิวเตอร์ในห้องแล็บก็ใช้ได้ ข้อมูลไม่ออกนอกอาคาร สอดคล้องกับนโยบายความปลอดภัยข้อมูล

เมื่อเทียบกับ Traditional Simulation ที่ต้องใช้หุ่นจำลองราคาแพง, Online Course ที่เป็น Passive Learning, หรือ VR Training ที่ต้องมี Headset AeroMedica คือจุดสมดุลที่ Active Practice ได้ ออฟไลน์ได้ และต้นทุนเป็นศูนย์ครับ

## Q8: "เพิ่มสถานการณ์ใหม่ได้ไหม? สถาบันปรับแต่งเองได้ไหม?"

ได้ครับ ทุกสถานการณ์ขับเคลื่อนด้วย JSON ไฟล์เดียว

ในไฟล์ JSON กำหนดข้อมูลผู้ป่วยทั้งหมด ตั้งแต่ชื่อ อายุ สัญญาณชีพ อาการตรวจร่างกาย ประวัติ คำวินิจฉัยที่ถูกต้อง ไปจนถึง Deterioration Rate และ Protocol Sequence ที่ถูกต้อง

การเพิ่มสถานการณ์ใหม่ทำได้โดยสร้าง JSON ไฟล์ใหม่ใน data/scenarios แล้วเพิ่มในหน้า Scenario Select ไม่ต้องแก้ GDScript เลย

สถาบันสามารถปรับแต่ง เช่น เปลี่ยนสัญญาณชีพผู้ป่วย ปรับ Deterioration Rate ให้เร็วหรือช้าขึ้น เปลี่ยนจำนวนอุปกรณ์ แก้ไขฐานข้อมูลยา หรือเพิ่มภาษาที่สามผ่านไฟล์ CSV ได้ทั้งหมด

ปัจจุบันมี 7 ไฟล์ JSON สถานการณ์ ผู้ป่วย 14 คน 47 โรควินิจฉัย อุปกรณ์ 24+ BLS รายการ บวก 17 ALS รายการ 7 จังหวะหัวใจ ECG และ Translation keys 300+ รายการครับ
